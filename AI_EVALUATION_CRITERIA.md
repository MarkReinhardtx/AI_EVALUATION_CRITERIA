 
# Критерии оценки литературного AI-помощника

## 1. Бизнес-цель

Помогать пользователям быстро получать понятные и достоверные ответы на русском языке о русских писателях и их произведениях.

Система должна:

- возвращать подготовленные ответы из FAQ для известных запросов;
- использовать модель Qwen через Ollama для остальных вопросов;
- учитывать историю диалога;
- не выдумывать литературные факты;
- отвечать без технических ошибок и за приемлемое время.

## 2. Наблюдаемые результаты

1. Система правильно выбирает источник ответа: FAQ или Ollama.
2. Ответ соответствует вопросу пользователя.
3. Ответ содержит достоверные сведения о писателях и произведениях.
4. Ответ написан понятно и на русском языке.
5. Модель правильно использует историю диалога.
6. Пользователь получает ответ без серверной ошибки.
7. Ответ формируется за приемлемое время.

## 3. Критерии оценки результатов

| Наблюдаемый результат | Критерий | Способ проверки |
|---|---|---|
| Правильно выбран FAQ или Ollama | Точность маршрутизации | Сравнить поле `source` с ожидаемым источником |
| Ответ соответствует вопросу | Релевантность | Проверить, отвечает ли текст именно на заданный вопрос |
| Сведения правильные | Фактическая точность | Сверить авторов, произведения и факты с надёжными источниками |
| Ответ легко читать | Понятность | Проверить грамотность, краткость и отсутствие лишних символов |
| Ответ дан на русском языке | Языковое соответствие | Проверить язык основного текста ответа |
| Учтены предыдущие сообщения | Контекстная связность | Отправить два связанных вопроса подряд |
| Запрос выполнен без сбоя | Техническая стабильность | Измерить долю запросов без ошибок `5xx` |
| Ответ получен вовремя | Скорость ответа | Измерить время от отправки запроса до получения ответа |

## 4. Шкала оценки с примерами

Содержательные критерии оцениваются по шкале от 0 до 3.

### Релевантность

| Оценка | Описание | Пример |
|-------:|---|---|
|      0 | Ответ не относится к вопросу | На вопрос о Гоголе дан ответ о Толстом |
|      1 | Ответ относится к общей теме, но не решает задачу | Вместо произведений приведена только биография |
|      2 | Ответ в основном правильный, но неполный или содержит лишнее | Названо только одно произведение |
|      3 | Ответ полностью и прямо отвечает на вопрос | Перечислены основные произведения запрошенного писателя |

### Фактическая точность

| Оценка | Описание | Пример |
|---:|---|---|
| 0 | Присутствует критическая ошибка | Указано, что «Мёртвые души» написал Достоевский |
| 1 | Есть несколько ошибок или выдуманные сведения | Писателю приписаны несуществующие произведения |
| 2 | Основная информация верна, но есть небольшая неточность | Неточно указана дата |
| 3 | Все проверяемые сведения верны | Автор и произведения указаны правильно |

### Понятность

| Оценка | Описание |
|---:|---|
| 0 | Ответ невозможно понять |
| 1 | Ответ плохо структурирован или содержит много лишнего текста |
| 2 | Ответ понятен, но содержит лишние детали |
| 3 | Ответ краткий, грамотный и хорошо структурированный |

### Учёт истории диалога

Тестовый диалог:

1. `Кто написал роман «Преступление и наказание»?`
2. `Какие ещё произведения он написал?`

| Оценка | Описание |
|---:|---|
| 0 | Модель не понимает, к кому относится слово «он» |
| 1 | Модель выбирает неправильного писателя |
| 2 | Модель понимает контекст, но отвечает неполно |
| 3 | Модель правильно определяет Достоевского и называет его произведения |

### Маршрутизация

| Оценка | Описание |
|---:|---|
| 0 | Выбран неправильный источник ответа |
| 3 | Выбран ожидаемый источник: FAQ или Ollama |

## 5. Связь критериев с бизнес-метриками

| Критерий | Бизнес-метрика | Значение для пользователя |
|---|---|---|
| Релевантность | Доля успешно решённых запросов | Пользователь получает нужную информацию |
| Фактическая точность | Доля ответов без фактических ошибок | Пользователь может доверять системе |
| Понятность | Средняя оценка понятности | Ответ легко прочитать и использовать |
| Контекстная связность | Доля правильно обработанных уточнений | Пользователю не нужно повторять контекст |
| Точность маршрутизации | Доля правильных переходов в FAQ или Ollama | Используется подходящий источник ответа |
| Техническая стабильность | Доля запросов без ошибок `5xx` | Сервис остаётся доступным |
| Скорость | Среднее время ответа | Пользователь не ждёт слишком долго |

Главная сквозная бизнес-метрика — **доля запросов, в которых пользователь получил правильный, релевантный и понятный ответ**.

Запрос считается успешно обработанным, если:

- релевантность не ниже 2 баллов;
- фактическая точность не ниже 2 баллов;
- понятность не ниже 2 баллов;
- запрос завершился без технической ошибки.

## 6. Пороговые значения

| Метрика | Минимально необходимое значение | Целевое значение |
|---|---:|---:|
| Успешно обработанные запросы | 75% | 90% |
| Фактически корректные ответы | 80% | 95% |
| Релевантные ответы | 80% | 95% |
| Правильная маршрутизация FAQ/Ollama | 90% | 98% |
| Правильный учёт истории | 70% | 90% |
| Ответы на русском языке | 95% | 100% |
| Запросы без ошибок `5xx` | 95% | 99% |
| Среднее время ответа FAQ | не более 1 секунды | не более 0,5 секунды |
| Среднее время ответа Ollama | не более 15 секунд | не более 7 секунд |
| Средняя экспертная оценка | не ниже 2 из 3 | не ниже 2,7 из 3 |

## Условие готовности системы

Система считается готовой к использованию, если достигнуты все минимальные пороги и отсутствуют критические фактические ошибки. Целевой уровень качества достигнут, когда не менее 90% проверочных запросов успешно решают задачу пользователя.
