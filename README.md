# Критерии оценки литературного AI-помощника

## 1. Цель проекта

Цель моего приложения — помогать пользователю получать ответы на вопросы о русских писателях и их произведениях.

Приложение должно:

- отвечать на русском языке;
- давать правильные и понятные ответы;
- использовать готовый ответ из FAQ, если он там есть;
- обращаться к модели Qwen через Ollama, если готового ответа нет;
- помнить предыдущие сообщения диалога;
- работать без ошибок и не заставлять пользователя долго ждать.

## 2. Что должно получаться в результате

Чтобы понять, хорошо ли работает приложение, я буду проверять следующие результаты:

1. Приложение правильно выбирает FAQ или Ollama.
2. Ответ относится к вопросу пользователя.
3. В ответе нет выдуманных или неправильных фактов.
4. Ответ легко понять.
5. Ответ написан на русском языке.
6. Приложение учитывает предыдущие сообщения.
7. Запрос выполняется без ошибки сервера.
8. Пользователь получает ответ за приемлемое время.

## 3. Что и как я буду проверять

| Что проверяется | Как я это проверю |
|---|---|
| Выбор FAQ или Ollama | Посмотрю значение поля `source` в ответе |
| Соответствие вопросу | Проверю, отвечает ли текст именно на заданный вопрос |
| Правильность фактов | Сверю автора, произведения и другие сведения с надёжным источником |
| Понятность | Проверю, легко ли прочитать и понять ответ |
| Русский язык | Проверю, что основной текст написан по-русски |
| История диалога | Отправлю два связанных вопроса подряд |
| Работа без ошибок | Проверю код ответа и отсутствие ошибок `5xx` |
| Скорость | Измерю, сколько времени прошло до получения ответа |

## 4. Шкала оценки

Для проверки текста ответа я буду использовать оценки от 0 до 3.

### Соответствие вопросу

| Оценка | Что означает | Пример |
|-------:|---|---|
|      0 | Ответ совсем не по теме | Пользователь спросил о Гоголе, а система ответила о Толстом |
|      1 | Тема похожая, но ответа на вопрос нет | Пользователь попросил назвать произведения, а система рассказала только биографию |
|      2 | Ответ подходит, но он неполный | Система назвала только одно произведение |
|      3 | Ответ полностью отвечает на вопрос | Система назвала основные произведения нужного писателя |

### Правильность фактов

| Оценка | Что означает | Пример |
|---:|---|---|
| 0 | В ответе есть серьёзная ошибка | Система написала, что «Мёртвые души» создал Достоевский |
| 1 | В ответе несколько ошибок или выдуманные сведения | Писателю приписаны несуществующие произведения |
| 2 | Основной ответ правильный, но есть небольшая неточность | Неправильно указана дата |
| 3 | Все сведения правильные | Правильно указаны автор и его произведения |

### Понятность ответа

| Оценка | Что означает |
|---:|---|
| 0 | Ответ невозможно понять |
| 1 | Ответ запутанный и содержит много лишнего текста |
| 2 | Ответ понятный, но в нём есть лишние детали |
| 3 | Ответ простой, грамотный и понятный |

### Учёт предыдущих сообщений

Для этой проверки я сначала отправлю вопрос:

`Кто написал роман «Преступление и наказание»?`

Затем отправлю второй вопрос:

`Какие ещё произведения он написал?`

| Оценка | Что означает |
|---:|---|
| 0 | Модель не поняла, о ком идёт речь |
| 1 | Модель выбрала неправильного писателя |
| 2 | Модель поняла, что речь о Достоевском, но ответила неполно |
| 3 | Модель поняла контекст и правильно назвала произведения Достоевского |

### Выбор FAQ или Ollama

Здесь результат можно оценить проще:

- `0` — выбран неправильный источник ответа;
- `3` — выбран правильный источник ответа.

Например, запрос `Расскажи мне про писателя Пушкина` должен получить ответ из FAQ, если Пушкин есть в словаре `FAQ_ANSWERS`.

## 5. Как проверки связаны с целью проекта

Главная цель приложения — дать пользователю правильный и понятный ответ о русской литературе.

- Если ответ правильный, пользователь получает достоверную информацию.
- Если ответ соответствует вопросу, пользователь получает именно то, что хотел узнать.
- Если ответ понятный, его легко прочитать и использовать.
- Если история учитывается, пользователю не нужно повторять предыдущие сообщения.
- Если правильно выбирается FAQ или Ollama, приложение использует подходящий способ ответа.
- Если нет серверных ошибок, пользователь может нормально пользоваться приложением.
- Если ответ приходит быстро, пользователю не приходится долго ждать.

Для общей оценки я посчитаю:

- процент правильных ответов;
- процент ответов, которые соответствуют вопросу;
- процент запросов без серверных ошибок;
- процент правильного выбора FAQ или Ollama;
- среднее время получения ответа.

Если эти показатели становятся лучше, значит приложение лучше выполняет свою главную задачу.

## Итог

Я буду считать, что приложение работает достаточно хорошо, если достигнуты все минимальные результаты. Желаемый результат — не менее 90% запросов должны заканчиваться правильным, понятным и полезным ответом.
