# Критерии оценки литературного AI-помощника

## Шаг 1. Бизнес-цель

Цель приложения - помочь пользователю быстро получить правильный и понятный ответ на вопрос о русских писателях и их произведениях.

## Шаг 2. Наблюдаемые результаты

Чтобы понять, достигается ли цель я буду проверять результаты, которые можно увидеть и измерить:

пользователь получил ответ на свой вопрос;
ответ содержит правильные литературные факты;
ответ соответствует вопросу и предыдущим сообщениям;
ответ написан на русском языке и в понятной форме;
запрос выполнился без ошибки;
пользователю не пришлось долго ждать.

## Шаг 3. Критерии оценки

| Требование | Критерий |
|---|---|
| Модель должна знать русскую литературу | Знание предметной области |
| Ответ не должен противоречить известным фактам | Фактическая согласованность |
| Ответ должен соответствовать вопросу и истории диалога | Согласованность с контекстом |
| Ответ должен быть на русском языке, без лишних символов | Следование инструкциям |
| Ответ не должен содержать оскорбительный или опасный текст | Безопасность |
| Приложение должно правильно выбирать FAQ или Ollama | Правильность маршрутизации |
| Запрос должен выполняться без серверной ошибки | Стабильность |
| Работа приложения не должна требовать платного | Стоимость |


## Шаг 4. Шкала оценки с примерами

Для всех критериев используется одна простая шкала:

1 - требование выполнено
0 - требование не выполнено.

| Критерий | Оценка 1 | Оценка 0 |
|---|---|---|
| Знание предметной области | Модель дала полезный ответ по русской литературе | Модель не ответила или ответила не по теме |
| Фактическая согласованность | Все проверяемые факты верны | В ответе есть хотя бы один неверный или выдуманный факт |
| Согласованность с контекстом | Ответ соответствует вопросу и предыдущим сообщениям | Ответ не учитывает вопрос или историю диалога |
| Следование инструкциям | Ответ дан на русском языке, в нужном формате и без лишних символов | Нарушено хотя бы одно обязательное требование |
| Безопасность | Ответ не содержит оскорблений, токсичного текста и опасных рекомендаций | В ответе присутствует оскорбительный, токсичный или опасный текст |
| Правильность маршрутизации | Выбран правильный источник: FAQ или Ollama | Выбран неправильный источник |
| Время ответа | Ответ получен не дольше установленного времени | Ответ получен позже установленного времени |
| Стабильность | Запрос завершился с кодом "200" | Получена серверная ошибка "5xx" |
| Стоимость | Платный API не использовался | Возникли расходы на платный API |

### Примеры

Фактическая согласованность:

1 - система ответила: Роман “Война и мир написал Лев Толстой;
0 - система ответила: Роман “Война и мир” написал Гоголь.

Учёт контекста:

1. "Кто написал Преступление и наказание?"
2. "Какие ещё произведения он написал?"

1 - модель поняла, что речь идёт о Достоевском;
0 - модель не поняла, о каком писателе задан второй вопрос.

Маршрутизация:

1 - запрос "Расскажи мне про писателя Пушкина" вернул "source: FAQ", если Пушкин есть в "FAQ_ANSWERS";
0 - этот запрос был ошибочно направлен в Ollama.

## Шаг 5. Связь с бизнес-метриками

Главная бизнес метрика проекта - процент запросов, после которых пользователь получил правильный и полезный ответ.

Связь можно показать так:

правильные факты в 80% ответов → не менее 70% успешно решённых запросов;
правильные факты в 90% ответов → не менее 85% успешно решённых запросов;
правильные факты в 95% ответов → не менее 90% успешно решённых запросов.

## Шаг 6. Пороговые значения

Минимальное значение - результат, ниже которого приложение нельзя считать достаточно полезным.

Целевое значение - результат, к которому желательно прийти.
